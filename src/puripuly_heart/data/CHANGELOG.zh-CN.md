# 更新日志（简体中文）

与 CHANGELOG.md 相同的章节结构；未翻译的旧版本会自动回退显示英文。

## r331 — 2026-07-30

- 更新内容对话框不再截断较长的条目 — 高度现在会根据实际换行后的文字计算（中文和日文同样适用）
- 可以点击对话框外部关闭它，对话框内还新增了「更新后不再显示」复选框。设置中也有同一个开关（「更新后显示更新内容」），随时可以重新打开
- 如果你的应用去获取更新时文件仍在上传，应用现在会自动等待并重试（最多三次），而不是显示红色失败提示

## r330 — 2026-07-30

- 已命名的声音现在可以跨应用被识别：同一个人通过语音通话和通过 VRChat 游戏内语音听起来有明显差异（编解码器不同，还有距离和房间效果），所以单一声纹经常在另一处匹配失败，导致你每次会话都要重新命名。现在每个人可以保存多个声纹 — 为已命名的人再次命名，只是在教应用「他在那边是这个声音」，而不是把两者平均成谁都不像的东西。已保存的声音会原样保留

## r329 — 2026-07-30

- 更新内容对话框现在是一张小巧简洁的卡片，不再是一个巨大的面板：宽度约为原来的三分之一，标题简化为「rNNN 更新内容」，文字更紧凑，右下角只有一个关闭按钮

## r328 — 2026-07-30

- 更新内容对话框终于能打开了：对话框组件要求两个按钮，而更新通知只有「关闭」一个，因此每次启动都在显示的瞬间崩溃（只在日志里留下一行记录）。现在支持单按钮对话框 — 这也顺带修复了本地语音识别提示框的同一个潜在崩溃
- 更新标记现在会在显示对话框之前保存，显示问题再也不会让通知陷入永远失败的循环

## r327 — 2026-07-30

- 修复自动更新从未真正运行的问题：启动时的更新检查、重试逻辑和更新后的对话框全都被意外放进了一个来自测试时期的已禁用代码分支 — 迄今为止的每次更新其实都是你自己点击「检查更新」才发生的。整个更新系统现在真正会在启动时运行：检查、自动下载、自动应用、以及更新内容对话框。新增的安全测试可防止更新代码再次落入该死分支

## r326 — 2026-07-30

- 紧急修复：r325 每次启动都会崩溃（「'GuiController' object has no attribute 'settings_created_fresh'」）— r325 的修复在一个要求预先声明字段的类上设置了标记。如果你下载了 r325，请更新到 r326（应用无法启动时也无法自我更新 — 请重新运行安装程序或下载 zip）

## r325 — 2026-07-30

- 修复了从旧版本更新后第一次启动时更新对话框不出现的问题：「上一版本」标记当时还不存在，应用无法得知自己刚更新过，于是保持沉默。现在从 r321 或更早版本更新的用户在新版本首次启动时就能看到更新内容对话框（全新安装仍然安静启动）

## r324 — 2026-07-30

- 更新日志现在支持多语言：切换界面语言后，「新功能」面板和更新完成后的弹窗会立即以你的语言显示更新内容（较早的历史版本仍显示英文）

## r323 — 2026-07-30

- 更新完成后的提示现在是一个正式的对话框：「PuriPulyHeart+ 已更新到 rNNN — 更新内容」，完整列出本次更新的全部变化，并带有关闭按钮，不再是转瞬即逝的小提示

## r322 — 2026-07-30

- 自我更新完成后，应用现在会主动告诉你：下次启动时一次性显示新版本号和主要变化 — 不再有静默更新
- 启动时的更新检查现在会在前 10 分钟内多次重试（之前只尝试一次，失败后 2 小时内不再检查 — 时机不巧就会整个会话停留在旧版本）
- 已识别说话人的聊天行现在直接用名字作为标题：「Baby 02:14」而不是「已收到 · Baby 02:14」（颜色仍然表示消息方向）

## r321 — 2026-07-30

- 为声音命名现在符合预期：聊天中已有的每一行会立即从「说话人N」更新为名字，重新打开对话框会显示已保存的名字而不是空白输入框，刚命名的声音在本次会话中也不会再退回「说话人N」（名字本身一直有被正确保存 — 缺的只是反馈）

## r320 — 2026-07-30

- 悬浮字幕的拼音和中文行现在获得与翻译行（r317）相同的防孤行处理：略微超出的行会稍微缩小字体放进一行，确实很长的行会在自然断点处平衡地分成两行，而不是把一两个字孤零零留在底部（「…变回 / 来了。」）。同时覆盖逐字注音和整块布局两种模式

## r319 — 2026-07-30

- 紧急修复：r318 的说话人标签在正常启动时完全不显示 — 声纹匹配组件只在更改语言或提供商设置时才被接入，启动时从未连接。声纹一直在计算，只是无处可匹配。现在从第一句话开始就能正常打标签

## r318 — 2026-07-30

- 新功能：说话人识别。来电语音会在聊天中标记为「说话人1」「说话人2」…方便在多人通话中区分不同的人 — 点击标签还可以为熟悉的声音命名；已命名的声音在以后的会话中会被再次认出。声纹只保存在本机（settings 旁边的一个小 voices.json 文件），绝不上传。设置开关：「识别说话人」（默认开启）。非常短的语句不会打标签（音频太短无法生成可靠声纹），压缩通话中两个相似的声音偶尔可能被混淆

## r317 — 2026-07-30

- 应用现在会在启动时自我更新：自动下载在启动后 10 分钟内完成时，会直接重启进入新版本（你的会话设置会自动恢复）— 启动应用就等于启动最新版本。会话中途发现的更新仍会等你按下重启按钮。原有的「自动下载更新」设置可以关闭此功能
- 更新检查现在在中国大陆也能用：当 GitHub 的接口被屏蔽时，应用会改用 jsDelivr 镜像读取版本信息，所以你仍然能看到有更新和更新内容
- 悬浮字幕不再把一两个词孤零零留在单独一行：略微超出的行会稍微缩小放进一行，确实很长的行会在自然断点处分成平衡的两半（中文行绝不会以句尾标点开头）

## r316 — 2026-07-29

- 悬浮窗启动时不再拦截鼠标点击：之前短暂的「悬浮窗已激活」横幅要求窗口可交互才能显示，导致每次启动都会吞掉几秒钟的点击。锁定启动时不再显示横幅 — 悬浮窗从第一帧起就是点击穿透的，主界面按钮已经能显示激活状态

## r315 — 2026-07-29

- 修复悬浮窗静默失效但仍显示为「已连接」的问题：一个罕见的启动时序冲突（第一条字幕恰好在窗口调整大小时到达）可能悄无声息地杀死悬浮窗的消息接收 — 窗口还在屏幕上、连接还在，但再也不显示任何内容，直到手动开关。现在悬浮窗监视应用每秒一次的心跳，30 秒收不到就自动重启；静默失败路径会记录日志并重启；应用端也能检测到失效的连接而不是永远报告「已连接」

## r314 — 2026-07-29

- 麦克风测试的百分比现在使用与其他语音软件相同的分贝刻度：正常说话约 50-60%，喊叫接近顶端，100% 表示爆音。之前 100% 对应原始数字最大值，导致再响亮健康的麦克风也只显示个位数，看起来像坏了

## r313 — 2026-07-28

- 日志文件现在自己就能回答音频问题（无需开启任何设置）：每个通道实际打开了哪个采集设备（名称、采样率、声道数）、送入语音识别的每个片段的响度、每分钟一次的「速率」检查（能暴露设备实际输出与声称的采样率不符的情况）、以及每 2 分钟对所有输出设备实际音量的巡检 — 日志能直接显示通话声音是否在应用没有监听的设备上播放

## r312 — 2026-07-28

- 又有四类噪音幻觉会在进入聊天或 VRChat 之前被拦截（全部来自真实用户日志）：整条消息只有「# 2」到「# 27」的数字墙、带数字的固定短语（「…的答案是：100」）、同一短语连说两遍（「格力空调，格力空调」）、以及长模板/递归循环（「这个角色的身高和体重的比是1.75:60」×8、递归的小明故事）。仅仅包含这些字词的真实句子不受影响

## r311 — 2026-07-28

- 「本地语音识别不可用」的警告不再推荐 Deepgram 或跳转外部 GitHub 指南（两者都属于原上游项目，与本分支无关）。现在它解释真正的原因 — 到达模型的是噪音或静音 — 以及应该检查什么：Windows 默认麦克风、PEER 监听的设备（远程桌面工具和虚拟声卡是常见原因）、以及「麦克风噪音抑制」设置

## r310 — 2026-07-28

- 撤销 r308：告诉语音模型该听哪种语言会让它把短句翻译而不是转写（日语音频出来变英文句子，英文音频出来变中文）。长而清晰的句子掩盖了这个问题，短句暴露了它。来电语音重新按实际说的语言转写

## r309 — 2026-07-28

- 翻译关闭时，来电语音不再因为「语言不对」而被隐藏 — 你能看到听到的一切，无论对方说什么语言。按语言过滤只在实际翻译时生效
- 只要可能出现任何语言（翻译关闭或语音自动检测开启），收到的每一行都会标注检测到的语言（[EN]、[ZH]…），让你始终知道识别器认为自己听到了什么
- 翻译卡片的提示文字在翻译关闭时会明确说明这一点

## r308 — 2026-07-28

- 使用本地 Qwen 模型时，收到的英语（或任何语言）不应再以中文出现：你设置的伙伴语言现在会传给识别器，让它不再自己猜。在嘈杂的游戏音频上，猜测正是把英语说成流利中文的原因。「自动检测」仍由模型自行判断（此更改已在 r310 撤销）

## r307 — 2026-07-28

- 修复了「怪怪怪怪…」式的失控消息进入聊天：重复检测器只认识从行首开始的循环，前面有几个正常字符就能溜过去
- 本地语音模型在静音时的固定输出（「的答案」「虚构」…）现在在麦克风和来电语音两个通道上都按幻觉处理

## r306 — 2026-07-28

- 修正了此列表中显示的日期：r304 和 r305 被标为 07-27，实际构建于 07-28

## r305 — 2026-07-28

- 新增「麦克风自动增益」（设置中，默认开启）：过小的麦克风音量会在语音识别前被内部提升到稳定水平，低音量不再导致你的话没被听到。别人听到的声音不变
- 近乎静音的音频不再变成凭空捏造的文字：当片段基本是静音时，识别结果必须有高得多的置信度才会被接受 — 从源头消灭「虚构」「的答案是」这类杂讯，而不是逐条拉黑

## r304 — 2026-07-28

- 修复「悬浮窗启动超时」：3 秒的限制太紧 — 更新后的首次启动（Windows 正在扫描新文件）经常超过它。现在是 20 秒
- 修复 r303 过于严格的问题：「目标语言」字段同时决定你的伙伴说什么语言，所以你自己的语言在那里重新可选（英语用户和说英语的伙伴需要它）。同语言屏蔽仍适用于真正的翻译对

## r303 — 2026-07-27

- 语言选择器现在会灰掉当前配对的另一半（按标签页），无法再选择英语→英语、中文→中文这类无意义的同语言组合 — 适用于「你的语言」「目标语言」、额外目标语言和对方注音语言

## r302 — 2026-07-27

- 修复在 SteamVR 中时，对方声音采集卡在无声耳机上的问题：当采集设备为「默认」且陷入静默时，应用会检查其他输出设备上是否有实际声音并跟过去（SteamVR 通过头显播放但不改变 Windows 默认设备 — 采集之前会永远停在耳机上）。进出 VR 双向生效

## r301 — 2026-07-27

- 修复「麦克风噪音抑制」和「对方音量自动增益」显示为「快速响应」/「稳定」而不是开/关的问题 — 那些文字属于低延迟设置，被误用导致新开关无法理解

## r300 — 2026-07-27

- 紧急修复：r299 启动即崩溃（「No such file or directory: …qwen3-asr-0.6b-int8-sherpa.manifest.json」）— 一次清理误删了构建中的语音模型清单。如果你下载了 r299，请更新到 r300（或重装）
- 构建流程现在缺少该清单时会拒绝打包，此问题不会再次发生

## r299 — 2026-07-27

- 新增「对方音量自动增益」（设置中，默认开启）：过小的桌面音频会在语音检测前被提升到稳定的内部水平，Windows 音量低或通话压低音量不再把歌曲/说话切成一个词一个词的碎片。播放音量不受影响 — 你听到的没有任何变化

## r298 — 2026-07-27

- 新增「麦克风噪音抑制」选项（设置中，麦克风灵敏度旁）：在语音识别前清除风扇、空调等持续背景噪音 — 适用于说话被当成噪音吃掉的环境。默认关闭
- 3 次无法识别的麦克风转写后，聊天会显示可操作的提示（检查输入设备/开启噪音抑制），而不是沉默到第 20 次
